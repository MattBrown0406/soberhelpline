- Zoom admin auto-registration removal clears only auto_register on every loaded active row for a normalized email, using existing admin RLS and verifying returned rows; historical opt-ins must all be cleared because the recurring job reads every active row.
- Admin abandoned-booking removal closes the selected lead using the existing completed flag and verifies the returned row; this preserves history while excluding the lead from the open list and future abandoned-booking follow-ups.
- Monday notification releases use the standalone private ledger with runner-owned transactions and a disabled deployed-revision probe before operator activation; preserve historical holds because legacy delivery coverage is uncertified.
- Family Squares auto-registration skips mistyped addresses and non-members with no attendance in the last 8 meetings (matched by registration, then Zoom email, then full name); re-engagement emails those people only on the first Monday of the month. Both fail open to the old behavior if a lookup fails. Never put registrant emails in code or migrations: this repository is public.

- Member-area tables use plain user UUIDs and profile-deletion cleanup rather than auth foreign keys; this preserves the managed-auth boundary, with cleanup failures recorded as warnings instead of blocking account deletion.
- Member forum reads use the owner-rights secure view and polling, with base-table author IDs withheld from authenticated clients; this masks anonymous authors while retaining membership/staff access checks.
- Preserve the generated cron-auth helper and use managed HTTP scheduling controls rather than hand-authored HTTP cron SQL; this keeps callback credentials under platform management.
- Keep private-guide startup isolated from site bootstrap; catch both startup imports with a single storage-guarded document retry and a visible fallback so transient fetch failures cannot leave a blank screen or reload loop.
